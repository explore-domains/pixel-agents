<task type="auto">
  <name>Task 1: Bound hook queue processing and guard stale event dispatch</name>
  <files>server/src/httpServer.ts, server/src/hookEventHandler.ts</files>
  <action>
  Harden the live event path before the final UX pass so overloads cannot destabilize the office.

  1. In `server/src/httpServer.ts`, keep the hook queue bounded by a fixed maximum size and evict the oldest pending item on overflow instead of letting the queue grow without limit. Keep a single processing loop with a safe `finally` reset so no stuck queue blocks future events.
  2. Reject malformed or weakly-typed payloads before enqueueing: only accept events with the expected session identifier and provider metadata. This prevents an invalid event from entering the async queue and causing downstream crashes.
  3. In `server/src/hookEventHandler.ts`, guard session routing against stale or duplicate events: skip dispatch when the agent/session has already ended, when the provider mapping is unknown, or when the payload repeats an already-handled session start. Preserve the existing lifecycle logic but short-circuit invalid states before `handleEvent()` mutates agent state.
  4. Keep the fix local to the queue and dispatch boundary — do not add a broad new infrastructure layer or rewrite the provider model. The goal is minimal, crash-safe hardening at the trust boundary.

  This creates the safety net required to keep the office responsive under bursty hook traffic without crashing CLI sessions.
  </action>
