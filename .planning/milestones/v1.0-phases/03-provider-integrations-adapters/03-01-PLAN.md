<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local CLI → HTTP hook server | Raw payloads from Antigravity, Gemini CLI, OpenCode, and Copilot arrive from local processes on loopback |
| hook server → normalized event pipeline | Provider payload data is converted to canonical AgentEvent objects before UI dispatch |
| UI + extension metadata | Product surface must reflect the ED Pixel Agents identity without leaking stale provider assumptions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | `POST /api/hooks/:providerId` | mitigate | Reuse the shared bearer-token validation and provider-scoped session keys so untrusted payloads cannot impersonate a valid provider |
| T-03-02 | Tampering | provider adapter normalization | mitigate | Normalize each raw payload in its provider module before downstream use; reject malformed or unsupported event envelopes early |
| T-03-03 | Denial of Service | multi-provider queue load | mitigate | Keep hook processing bounded and rely on single canonical event dispatch to avoid provider-specific loops or duplicate buffering |
| T-03-04 | Repudiation | adapter registry | mitigate | Record provider ID and session ID in the single normalizing path so lifecycle activity remains attributable |
| T-03-05 | Information Disclosure | UI metadata / extension names | accept | Branding is user-visible and only changes presentation; it does not expose additional secrets or workspace data |
</threat_model>
